# MLOps Health Service

Асинхронный сервис на FastAPI для лабораторной работы по MLOps. Проверяет
доступность приложения и PostgreSQL, возвращает версию приложения, версию БД
и время проверки подключения.

## Стек

- Python 3.12+, uv — управление проектом и зависимостями.
- FastAPI и Uvicorn — HTTP API и ASGI-сервер.
- asyncpg — асинхронный доступ к PostgreSQL.
- Pydantic Settings — конфигурация из окружения и `.env`.
- Ruff — статический анализ и форматирование.

Зависимости разделены на группы `web` и `dev`. Обе группы устанавливаются
по умолчанию командой `uv sync`.

## Структура проекта

```text
src/
├── main.py                      # Пустой файл; для запуска не используется
└── mlops_health_service/
    ├── __init__.py
    ├── config.py                # Настройки приложения и PostgreSQL
    └── main.py                  # FastAPI, lifespan, модели ответов и эндпоинты
pyproject.toml                   # Метаданные, зависимости и настройки Ruff
uv.lock                         # Зафиксированные версии зависимостей
Dockerfile                      # Описание контейнерного образа
```

## Локальный запуск

Потребуются Python 3.12 или новее, установленный uv и доступный PostgreSQL.
Команды выполняются из корня репозитория.

1. Установите проект и зависимости из lock-файла:

   ```bash
   uv sync --frozen
   ```

2. Создайте в корне файл `.env` и укажите параметры своей БД:

   ```dotenv
   DATABASE__DATABASE_URL=postgresql://postgres:postgres@localhost:5432/mlops
   DATABASE__DB_POOL_MIN_SIZE=0
   DATABASE__DB_POOL_MAX_SIZE=10
   DATABASE__DB_COMMAND_TIMEOUT=5
   ENVIRONMENT=development
   LOG_LEVEL=INFO
   ```

   Имя пользователя, пароль, адрес и имя базы в примере замените своими.
   База должна быть создана заранее. Файл `.env` исключён из Git.

3. Запустите приложение:

   ```bash
   uv run uvicorn mlops_health_service.main:app --host 127.0.0.1 --port 8000 --reload
   ```

Swagger UI доступен по адресу <http://127.0.0.1:8000/docs>.

## Конфигурация

Настройки читаются из переменных окружения и `.env`; переменные окружения
имеют приоритет. Двойное подчёркивание отделяет вложенные поля.

| Переменная | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `DATABASE__DATABASE_URL` | Обязательная | Строка подключения к PostgreSQL |
| `DATABASE__DB_POOL_MIN_SIZE` | `0` | Минимальное число соединений |
| `DATABASE__DB_POOL_MAX_SIZE` | `10` | Максимальное число соединений |
| `DATABASE__DB_COMMAND_TIMEOUT` | `5.0` | Таймаут SQL-команд в секундах |
| `ENVIRONMENT` | `development` | `development`, `staging` или `production` |
| `LOG_LEVEL` | `INFO` | `DEBUG`, `INFO`, `WARNING` или `ERROR` |

Поля `ENVIRONMENT` и `LOG_LEVEL` пока только загружаются в настройки:
отдельная настройка логирования через них не реализована.

## API

### `GET /healthz`

Быстрая проверка того, что процесс отвечает. Не обращается к БД.
При работающем приложении возвращает HTTP 200:

```json
{"status": "healthy"}
```

### `GET /api/v1/version`

Возвращает HTTP 200 и версию установленного пакета `mlops-health-service`.
Источник версии — метаданные проекта из `pyproject.toml`.

```json
{"version": "0.1.0"}
```

Проект должен быть установлен, например командой `uv sync`, чтобы его
метаданные были доступны через `importlib.metadata`.

### `GET /api/v1/health`

Получает соединение из общего пула и выполняет `SHOW server_version`.
Время проверки включает ожидание соединения и выполнение запроса;
общий таймаут этой операции — 5 секунд.

При успехе возвращает HTTP 200. Пример ответа:

```json
{
  "status": "healthy",
  "database": "connected",
  "response_time_ms": 2.35,
  "db_version": "17.0"
}
```

При ошибке или превышении таймаута возвращает HTTP 503:

```json
{
  "status": "unhealthy",
  "database": "disconnected",
  "response_time_ms": 5001.42,
  "db_version": null
}
```

Числа времени и версия PostgreSQL приведены для примера. Ошибка проверки
записывается в лог со стеком вызовов.

Пул создаётся в lifespan при старте приложения и закрывается при завершении.
Ошибка создания пула может прервать запуск приложения; в таком случае
HTTP-эндпоинты ещё недоступны.

Проверить ответы можно через Swagger UI или терминал:

```bash
curl http://127.0.0.1:8000/healthz
curl http://127.0.0.1:8000/api/v1/version
curl -i http://127.0.0.1:8000/api/v1/health
```

## Проверка оформления

```bash
uv run ruff check src
uv run ruff format --check src
```

Для применения форматирования:

```bash
uv run ruff format src
```

Ruff настроен на Python 3.12 и длину строки 100 символов. Проверяются
импорты, аннотации, именование и другие правила из `pyproject.toml`.

## Текущее состояние

Реализованы три эндпоинта, конфигурация и проверка PostgreSQL. В репозитории
есть Dockerfile с отдельным пользователем и проверкой `/healthz`, но сборка
контейнера пока требует проверки: установка пакета выполняется до копирования
его исходников.

Тесты, Docker Compose, pre-commit и CI/CD пока не добавлены. Зависимости для
тестирования уже перечислены в группе `dev`.
